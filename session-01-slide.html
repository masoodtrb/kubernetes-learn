ماشین مجازی

VM

Hypervisor ← سیستم‌عامل مهمان کامل ← برنامه
  • سنگین‌تر و معمولاً دیرتر آماده می‌شود
  • مرز ایزوله‌سازی در سطح VM
  • مناسب اجرای سیستم‌عامل‌های متفاوت
کانتینر

Docker

سیستم‌عامل میزبان و Kernel مشترک ← فرایند ایزوله
  • سبک‌تر و معمولاً سریع‌تر برای شروع
  • ایزوله‌سازی در سطح فرایند؛ مدل امنیتی متفاوت
  • مناسب بسته‌بندی و اجرای یکسان اپ
Container معمولاً سیستم‌عامل مهمان جدا ندارد؛ روی Kernel میزبان تکیه می‌کند. بنابراین Container و VM جایگزین یک‌به‌یک هم نیستند.
سبک‌تر، اما با مرز ایزوله‌سازی متفاوت۰۵
۰۵ · Dockerfile برای فرانت

از HTML ساده تا Image نهایی

FROM nginx:1.27-alpine COPY index.html /usr/share/nginx/html/index.html EXPOSE 80

docker build، Image را می‌سازد؛ docker run از آن Container روشن می‌کند.

۱FROM — Image پایه، مثلاً nginx یا node
۲COPY — انتقال فایل از build context به Image
۳EXPOSE — مستندسازی پورت داخلی؛ به‌تنهایی پورت میزبان را باز نمی‌کند
نمونهٔ اجرا: docker run --rm -p 8080:80 fe-docker-simple
مرورگر به پورت ۸۰۸۰ میزبان وصل می‌شود؛ nginx داخل Container پورت ۸۰ را سرو می‌کند.
WORKDIR پوشهٔ کاری RUN فرمان زمان ساخت CMD فرمان شروع Container
EXPOSE پورت را publish نمی‌کند؛ -p این کار را انجام می‌دهد۰۶

شبکهٔ داخلی

در شبکهٔ Compose، سرویس‌ها با نام سرویس همدیگر را پیدا می‌کنند.

http://api:3000

EXPOSE

در Dockerfile: فقط مستند می‌کند که برنامه داخل Container چه پورتی دارد.

expose

در Compose: پورت داخلی شبکه را مشخص می‌کند؛ برای انتشار به میزبان نیست.

داخل Container، localhost یعنی همان Container؛ برای دسترسی به API همسایه از نام سرویس مثل api استفاده کن.
نام سرویس در Compose نقش DNS داخلی دارد۰۹
۰۹ · Docker Compose

چند سرویس، یک فایل، یک دستور

services: web: build: context: . dockerfile: Dockerfile.web ports: - "8083:80" depends_on: - api api: build: context: . dockerfile: Dockerfile.api expose: - "3000"
۱services: واحدهای اپ مثل web و api
۲ports: فقط web از میزبان قابل‌دسترسی می‌شود
۳depends_on: ترتیب شروع را مشخص می‌کند؛ سلامت سرویس را تضمین نمی‌کند
۴شبکهٔ پروژه خودکار ساخته می‌شود؛ web به http://api:3000 وصل می‌شود
برای توسعه و دمو روی یک ماشین: docker compose up --build · توقف و پاک‌سازی: docker compose down

Compose راهی ساده برای بالا آوردن فرانت، API آزمایشی و سرویس‌های وابسته کنار هم است.

خودترمیمی مقدماتی

اگر نمونه‌ای از کار بیفتد، ارکستراتور برای رسیدن به وضعیت مطلوب تلاش می‌کند.

Swarm اینجا پل مفهومی است، نه هدف نهایی: replica و وضعیت مطلوب را می‌شناسیم؛ در جلسهٔ بعد سراغ Deployment و Kubernetes می‌رویم.

شش نکته برای به‌خاطر سپردن

۱Image قالب است؛ Container اجرای آن.
۲Container سبک‌تر از VM است، اما Kernel میزبان را به‌اشتراک می‌گذارد.
۳برای فرانت، multi-stage خروجی build را از ابزارهای ساخت جدا می‌کند.
۴-p برای دسترسی از میزبان است؛ نام سرویس برای ارتباط داخلی Compose.
۵Compose چند سرویس را با یک تعریف روی یک میزبان اجرا می‌کند.
۶Swarm مقدمهٔ مفهوم ارکستراسیون است؛ گام بعدی Kubernetes.
