# کنداکتور دوره Docker — چپتر فرانت (قبل از Kubernetes)

## هدف دوره

آشنایی عملی اعضای چپتر فرانت با Docker از صفر تا سطح قابل‌استفاده روزمره، تا بتوانند:

- بفهمند Image / Container چه تفاوتی با VM دارند
- Dockerfile ساده تا نسبتاً حرفه‌ای برای یک اپ فرانت بنویسند
- چند سرویس را با Docker Compose بالا بیاورند
- مدل ذهنی Docker Swarm را به‌عنوان ارکستراسیون سبک بشناسند (پل به Kubernetes)

## مخاطب

- اعضای چپتر فرانت (آشنا با وب و JS/TS)
- آشنایی قبلی با Docker لازم نیست
- ترمینال پایه کافی است

## پیش‌نیازها (قبل از جلسه)

| مورد | سطح | توضیح |
|------|------|--------|
| ترمینال پایه | عملی | `cd`, کپی دستور، خواندن خروجی |
| Node.js / npm | اختیاری | فقط اگر بخواهند اپ خودشان را build کنند |
| Docker Engine یا Docker Desktop | برای دمو و تکلیف | `docker version` باید کار کند |

## جایگاه در مسیر یادگیری چپتر

```text
Docker (این دوره، ۹۰ دقیقه)
  → Docker Compose
    → Docker Swarm (مقدماتی)
      → Kubernetes (دوره جدا در ریشهٔ ریپو)
```

بدون این جلسه، جلسهٔ Kubernetes فرض می‌کند مخاطب «مفهوم Container» را می‌داند؛ این دوره همان پیش‌نیاز را پر می‌کند.

## نقشه جلسه (یک جلسهٔ ۹۰ دقیقه‌ای)

| بازه | موضوع | خروجی یادگیری |
|------|--------|----------------|
| ۰–۵ | خوش‌آمد، هدف، چک محیط | همه می‌دانند امروز چه می‌گیریم |
| ۵–۱۵ | تاریخچهٔ کوتاه Container / Docker | چرا Docker فراگیر شد |
| ۱۵–۳۰ | مقایسه با سایر Virtualizationها | VM ≠ Container؛ مدل ذهنی درست |
| ۳۰–۵۵ | Dockerfile: ساده → نیمه‌حرفه‌ای → پیشرفته (+ جیب دستورات ۲–۳ دقیقه) | خواندن و نوشتن Dockerfile فرانت؛ دستورات روزمره |
| ۵۵–۷۰ | Docker Compose | چند سرویس با یک فایل |
| ۷۰–۸۵ | Docker Swarm | ارکستراسیون سبک و پل به K8s |
| ۸۵–۹۰ | جمع‌بندی، تکلیف، نظرسنجی | مسیر ادامه مشخص است |

جزئیات کامل اسکریپت: [session-01.md](./session-01.md)

## تایم‌باکس مرجع سریع

| بازه | موضوع |
|------|--------|
| ۰–۵ | خوش‌آمد و هدف |
| ۵–۱۵ | تاریخچه |
| ۱۵–۳۰ | Docker در برابر Virtualization |
| ۳۰–۴۰ | Dockerfile ساده + دمو `docker build/run` + جیب دستورات پرکاربرد (۲–۳ دقیقه؛ اگر کم آمد فقط جدول) |
| ۴۰–۵۰ | Dockerfile نیمه‌حرفه‌ای (multi-stage سبک) |
| ۵۰–۵۵ | Dockerfile پیشرفته (نکات امنیتی و بهینه‌سازی) — فشرده |
| ۵۵–۷۰ | Docker Compose + دمو |
| ۷۰–۸۵ | Docker Swarm + دمو حداقلی / walkthrough |
| ۸۵–۹۰ | جمع‌بندی و تکلیف |

اگر وقت کم آمد (اولویت حذف):

1. بخش «پیشرفته» Dockerfile را به بولت‌های ۳ دقیقه‌ای کاهش دهید
2. دمو Swarm را زنده نکنید؛ از YAML ازپیش‌آماده‌شده روی صفحه بخوانید
3. تاریخچه را به ۳ دقیقه فشرده کنید
4. جیب دستورات پرکاربرد را به نشان‌دادن جدول محدود کنید؛ جزئیات در [commands.md](./commands.md)

اگر وقت زیاد آمد:

- با هم یک `COPY` اشتباه را debug کنید (`docker history` / لایهٔ cache)
- یک سرویس دوم به Compose اضافه کنید
- یکی دو فلگ از چیت‌شیت (`-d`, `--name`, `logs -f`) را زنده نشان دهید

## چک‌لیست آماده‌سازی ارائه‌دهنده

### یک روز قبل

- [ ] `docker version` و `docker compose version` کار می‌کنند
- [ ] فایل‌های داخل [demo/](./demo/) حداقل یک‌بار build/run شده‌اند
- [ ] Imageهای پایه کش شده‌اند: `nginx:1.27-alpine`, `node:22-alpine`
- [ ] لینک این داکیومنت برای شرکت‌کنندگان آماده است
- [ ] پلن B: اسکرین‌شات / خروجی ازپیش‌گرفته‌شده اگر شبکه یا Docker Desktop گیر کرد

### ۳۰ دقیقه قبل

- [ ] Containerها و Stackهای دموی قبلی پاک شده‌اند
- [ ] فونت ترمینال بزرگ است
- [ ] تایمر ۹۰ دقیقه‌ای آماده است
- [ ] اگر Swarm دمو می‌کنید: `docker swarm init` را از قبل زده‌اید یا آمادهٔ init هستید

### حین ارائه

- [ ] از kernel namespace / cgroups عمیق نشوید مگر سوال بیاید
- [ ] هر مفهوم را با یک جمله «برای فرانت یعنی چه؟» ببندید
- [ ] حداقل یک‌بار از اتاق بخواهید خروجی `docker ps` را با هم بخوانند
- [ ] Swarm را به‌عنوان «مقدمهٔ ارکستراسیون» بفروشید، نه جایگزین کامل Kubernetes

بعد از این جلسه (و تکلیف)، مخاطب باید بتواند:

- [ ] تفاوت Image و Container را بگوید
